WaveLab — convolution reverb

The processor is built, tested and in the Add Effect menu; its output matches a direct time-domain convolution to 149 dB. It has one thing no other built-in has: its identity is a file, and the rack card only knows how to draw sliders. This is the one row that has to be added — the same shape as the plugin editor button already on a VST3 card, and nothing else about the card changes.

Why it is a row and not a button

A button would say what you can do and never what you did. The plugin editor button on a VST3 card gets away with that because the card already carries the plugin's name — here the file is the setting, and a card that reads only Load… cannot tell you which room you are in. So the row names the response and states what it is: how many channels, how long, and the rate it was recorded at.

The third state is the one worth designing for. A preset stores the path, so a rack moved between machines — or a drive that was not plugged in — arrives naming a file that is not there. It keeps the name, says plainly that it is missing, and offers to find it, rather than silently loading nothing and leaving the reverb apparently switched on and inaudible. The effect passes audio through untouched in the meantime, which the amber readout already says.

Nothing else about the card changes. Same strip colour as the other time-and-modulation effects, same header, same auto-generated sliders. The row sits between the divider and the first parameter, which is where a VST3 card's editor button sits, and is the only markup being added.
