Custom target ceiling
The ceiling stops being a three-item list and becomes a value you set: a slider over the analyzer's real range, −1.0 to −24.0 dBTP in 0.5 dB steps. It is settable in Settings and, because the analyzer re-derives a recommendation from blocks it has already stored, directly on the level-check card mid-transfer — with no rescan.

Peak the Recording Level Assistant aims a transfer at. −6 dBTP suits vinyl and tape transfers that will be declicked or restored afterwards: repairing a click or a flat top can put the reconstructed peak back above what was captured, and −3 dBTP leaves almost no room for that. Go lower for sources you expect to need heavy repair.

2 · Any value, not three

Three positions of the same control. A stored value is now clamped into range and snapped to the nearest 0.5 dB rather than being thrown away for not matching the list — so a hand-edited settings.json survives.

5 · What moves when the ceiling moves

Everything downstream is derived, so one drag re-paints all of it — this is the reason it is worth having on the card at all rather than only in Settings.
INPUT METER · TARGET BAND FOLLOWS THE CEILING

The band sits at ceiling − reserve ± 1 dB, so it slides as either changes.
Re-derived on the spot — RecordingLevelAnalyzer.TargetCeilingDb already clears the cached snapshot and bumps the analysis generation when it is set, so a new recommendation, projected peak, reserve and meter band all come back from blocks already in history. No rescan, no capture-thread work.
Persistence — the fixed RecordingTargetCeilingChoicesDb list stops being the validator. AppSettings.Normalize clamps to −1…−24 and snaps to 0.5 dB, keeping −6 only for a value that is missing or not a number.
Two owners, one value — the card writes back to AppSettings, so a ceiling found mid-transfer is the one the next session opens with, and the Settings slider shows it.
