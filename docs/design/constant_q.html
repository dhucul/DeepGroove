WaveLab — constant-Q spectrogram

The spectral editor already draws its frequency axis logarithmically — that shipped, and it is the default. What it does not have is a constant-Q analysis. The two sound alike and are not: today a linear transform is stretched onto a log axis, so the bins are still 21.5 Hz apart everywhere. At the bottom of the picture that is four bins spread over a third of the height, and at the top it is two hundred bins crushed into a centimetre. A constant-Q analysis gives every octave the same number of bins instead, which is where a musician's ear already is.

Three scales, not two. LINEAR and LOG are the axis the existing analysis is drawn on and cost nothing to switch between. CONSTANT-Q is a different transform, so it is in the same control rather than a separate one — the user is choosing how the picture is made, and the fact that two of the choices happen to share an analysis is this app's business, not theirs. Bins per octave appears only for constant-Q, because it is the only one for which the phrase means anything.

3 · What it buys, and what it costs

At the bottom, resolution. A 2048-point transform at 44.1 kHz has bins 21.5 Hz apart, so 50 Hz mains and 60 Hz mains are two bins apart and their harmonics smear together — the picture cannot show you which one a transfer has, and that is the first thing anyone wants to know about a hum. Constant-Q at 36 bins per octave puts about 2 Hz between bins down there.

At the top, time. The same fixed transform spends 1024 bins above 5 kHz and a 46 ms window on all of them, so a click is three frames wide however short it was. Constant-Q shortens the window as the frequency rises, so the top of the picture gets sharper in time exactly where the things worth seeing are brief.

The cost is that it is a second analysis. Constant-Q is not a re-drawing of what is already computed, so switching to it re-analyses, and it is slower than an FFT per frame. It goes behind the same tiled bitmap cache the existing display uses, keyed on the scale as well as the size and window, so panning and zooming do not pay for it twice.

It does not change what a repair works on. The mask is already defined in the repair grid — anchored at sample zero, at the hop and transform length spectral edits use — rather than in whatever grid the display happened to analyse at, precisely so the display can change without the edit changing. A selection drawn on a constant-Q picture maps back the same way one drawn at a different zoom already does. Nothing about Heal or Attenuate moves.
