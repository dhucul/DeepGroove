WaveLab — VST3 plugins

The VST3 engine is built and tested: out-of-process scanning with a cache, module loading, parameter discovery, interleaved processing, and a plugin editor window. None of it is reachable — there is no menu entry and no way to put a plugin in the rack. This is the way in. Three pieces: a plugin manager for scanning and vetting, a rack card so a plugin sits alongside the twenty-one built-ins, and the editor window that already exists.

Scanning is out of process and already implemented — each plugin is loaded by a child WaveLab with --vst3-scan, so a plugin that crashes on load takes the child down and is recorded as CRASHED rather than killing the app. Twenty seconds is the timeout. Results are cached against the binary's timestamp, so Rescan changed only is near instant and the full rescan is the slow path.

Rejections are shown, not hidden. A plugin that fails is more interesting than one that works — if something you paid for is missing you need to see why, not wonder whether the scan reached it. The reasons are the ones the scanner actually distinguishes: not an audio effect, no audio outputs, refused the stereo arrangement, failed to initialise, or crashed.

Params 0 is not a fault. Every one of the 22 plugins on this machine reports zero parameters and no editor, which is why the parameter and editor paths have never once been exercised against a real plugin. The column exists so that is visible at a glance rather than being discovered in the rack.

A plugin is an effect, not a special case. It gets a numbered card, a bypass LED, move up/down, reset and remove, exactly like the built-ins, and it saves into chain presets with them. The only visible differences are a violet category stripe instead of teal, the vendor on the second line, and the editor button — enough to tell at a glance that this one is somebody else's code.

Parameters are sliders like any other. VST3 exposes every parameter as a normalised 0…1 value plus a display string the plugin formats itself, so the card shows the plugin's own text (312 ms, 0.71) beside a plain slider rather than guessing at units. Parameters flagged hidden, read-only, or as the bypass are not listed — the bypass is the LED.

The empty case is stated, not left blank. A card with no sliders and no explanation reads as broken. Since every plugin on this machine lands in exactly that state, it is the case most likely to be seen first.

This window is already written — Vst3EditorWindow and Vst3EditorHost exist and host the plugin's HWND, honour its requested size, and forward resize negotiation. It has never been opened, because nothing can open it and no installed plugin has an editor to put in it.

Non-modal, one per plugin instance. Opening it must not stop playback — the point of a plugin editor is to turn a knob while listening. Closing the rack card closes the editor with it.

When there is no editor the button is absent rather than disabled-and-mysterious; the card falls back to the sliders, and if there are no parameters either, to the message in section 2.

What this does not do

No crash isolation at run time. Scanning is out of process; processing is not. A plugin that faults while playing takes WaveLab with it. Real sandboxed hosting means a separate audio process and shared-memory ring buffers — a project in its own right, not a detail of this one. The scan filter is the mitigation: a plugin that cannot survive being loaded never reaches the rack.

No automation, no parameter recording. Parameters are set from the rack and from the plugin's own editor, and the two stay in sync; nothing is recorded against time.

No plugin delay compensation across the chain. The rack is serial and offline renders already account for reported latency, so a latent plugin is handled — but nothing parallel-compensates.

Nothing here has been heard. That standing caveat applies to this as it does to phases 2–6: every one of the 22 plugins on this machine reports no parameters and no editor, so the parameter path, the editor path and this UI can only be verified against a plugin that publishes both. Installing one conventional plugin would settle it.
