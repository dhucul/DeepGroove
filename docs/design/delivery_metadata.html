WaveLab — PQ sheet editor & tag editor

The two dialogs left in the professional-delivery tier. The PQ sheet is the per-track catalogue information a pressing plant reads out of a DDP set — ISRC, performer, songwriter, pre-emphasis — none of which a cue sheet has anywhere to put, and none of which the app can fill today. The tag editor is the same idea for a single file: what goes into a WAV's bext and LIST/INFO chunks, an AIFF's NAME/AUTH/ANNO, and an MP3's ID3v2.4 frames. Both reuse the existing dialog chrome, field styling and button set.

What changes. Four columns are added to the existing track list — performer, songwriter, ISRC, pre-emphasis — plus disc performer and UPC beside the disc title, and a deliverable switch that replaces the separate format prompt. Start and length become read-out columns in CD timecode (mm:ss:ff, 75 frames a second) rather than the editable source-sample fields, because on a DDP those positions are derived from the sector-aligned plan and are not the user's to type. The dialog widens from 790 px to 1100 px to hold them. Validation is the existing one-line strip plus a per-field state: an ISRC that is not twelve characters after punctuation is stripped is marked and omitted rather than written short.

What it is. One new dialog behind File ▸ File Information…, three tabs on the existing segmented control. Description is the human-facing set and is the only one that reaches every format — LIST/INFO in a WAV, NAME/AUTH/ANNO in an AIFF, ID3v2.4 frames on an MP3 export. Broadcast is the bext chunk and is WAV-only; on an AIFF document the tab is present but disabled rather than hidden, so the reason it does not apply is visible. Chunks is a read-out, not an editor: it exists so the claim "your file's metadata survived" can be checked rather than believed.

What it reuses. Dialog chrome, header dot, segmented control, field and button styles are all existing. Nothing here needs a new control template.
