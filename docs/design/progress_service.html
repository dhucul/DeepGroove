Progress & cancel — a shared host for long operations

Today the DSP layer takes a CancellationToken and reports IProgress<T> almost everywhere, but the main-window commands throw both away and set a wait cursor: open, save, export, render, apply-chain and the sample-rate/stretch/pitch tools all freeze the window with no indication and no way out. Meanwhile five dialogs each hand-roll their own bar, their own token source and their own cancel-on-close handshake. This is one host for both.

How it behaves

Two tiers, one service. Work that mutates the document — open, save, export, render, apply chain, stretch, pitch, sample-rate convert — takes the overlay, because starting a second edit midway through the first is the bug you are preventing. Work that does not — peak rebuilds, cleanup analysis, autosave — takes the status strip and leaves the editor live.
The scrim starts below the menu bar. The title bar stays reachable so the window can still be moved, and closing during an operation cancels it and waits, exactly as the restoration and CD dialogs already do on their first X click.
Cancel is a request, not an event. The button latches to “Cancelling…” and disables, the bar desaturates, and the operation ends at its next cancellation point. Nothing claims to have stopped before it has.
Indeterminate is a real state, not 0%. Several existing paths report no total — MediaFoundationReader decode among them. Those get a moving band and an elapsed count rather than a bar that lies.
Nothing appears for fast work. The host waits ~400 ms before showing anything, so trimming a selection or saving a short file stays silent instead of flashing a dialog.
The five existing dialogs keep their own bars for now. They already work and each owns a bounded modal flow; folding them in is a follow-up, not a prerequisite. The win here is the main window, which has nothing at all.
Time remaining is only shown once it is worth trusting — after 5% and 3 s of progress, smoothed. Before that the right-hand slot shows elapsed.
Fonts, colours and the 25 px status bar are unchanged. The strip reuses the row that already holds autosave state and CPU/RAM; the overlay reuses the dialog styling from Settings and Export.
